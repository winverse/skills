project-structure

프로젝트 구조를 선택하거나 표준화할 때 폴더 경계, 도메인 우선 구조, 환경 변수, codegen, DB, 테스트, 보안, 상태 점검, 관측성, 인프라 인계를 한 번에 정리한다.

스킬 읽기용 단일 HTML · 한국어 우선 · 외부 asset 없음 · 인터랙션 없음

요약

  • 목적frontend, backend, full-stack monorepo, desktop app, 인프라-aware 구조를 도메인 경계와 실행 경계 기준으로 설계한다.
  • 사용할 때새 프로젝트 구조를 만들거나 기존 repo의 폴더, package, app, infra, folder-local instruction docs 경계를 정리할 때 사용한다.
  • 주요 입력제품/도메인 언어, runtime 요구, stack 선택, DB와 codegen 방식, 테스트와 배포 범위, 기존 repo 구조.
  • 주요 출력선택한 stack, 폴더 tree, bounded context map, 경계 설명, folder-local AGENTS.md 또는 CLAUDE.md, 검증 명령.
  • 선행 조건raw product discovery는 먼저 project-workflow가 처리하고, 이 스킬은 도메인 언어와 구조 질문이 구체화된 뒤 호출한다.

사용 판단

바로 사용 사용자가 frontend, backend, monorepo, desktop, infra-aware folder structure, DDD-lite domain-first folders, folder-local AGENTS.md index를 선택·생성·표준화·리팩터링하자고 할 때.
먼저 확인 stack 선택이 불명확하면 짧은 숫자 선택지로 확인하고, 기존 repo가 있으면 현재 구조와 package manager를 먼저 읽는다.
먼저 읽기 CONTEXT.md, CONTEXT-MAP.md, ADR, PRD, issue, folder-local instruction docs가 있으면 stack보다 먼저 읽어 도메인 용어와 bounded context를 확인한다.
사용하지 않음 원시 아이디어, 제품 검증, 도메인 인터뷰, PRD 작성이 아직 필요한 경우에는 project-workflow가 먼저다.

중요한 기준

  • 기본 stack명시가 없으면 Bun, Turborepo, Next.js, NestJS with Fastify, GraphQL, urql, GraphQL Code Generator, PostgreSQL + Drizzle, Panda CSS with headless UI, Tauri, Zod env validation을 기본값으로 둔다.
  • 인프라 조건사용자가 infra를 요청하지 않았으면 Pulumi, AWS, Docker 배포 구조를 추가하지 않는다. infra 요청 시 Pulumi, Docker, AWS ECR/ECS Fargate를 기본 경로로 둔다.
  • TypeScript module 정책TypeScript 구조는 ESM only로 설계한다. package.json의 type: "module", import/export, runtime에 맞는 tsconfig를 기본으로 둔다.
  • CommonJS 금지require, module.exports, exports.*, .cjs, .cts를 생성하거나 권장하지 않는다. 기존 CommonJS repo는 전환 boundary와 migration 단계를 표시한다.
  • DDD-lite중간 이상 규모, 장기 유지, 여러 agent/session 협업, 복잡한 business rule이 있는 프로젝트는 기술 계층만 있는 tree를 기본값으로 삼지 않는다.
  • 생성물 경계generated artifact와 source artifact를 섞지 않고, env, codegen, DB migration, test, health/readiness, observability 위치를 tree에 드러낸다.

작업 흐름

  1. 요구 확인제품/도메인 언어와 runtime 요구를 확인한다.
  2. 도메인 경계필요하면 DDD-lite 기준으로 bounded context와 domain-first folder map을 정한다.
  3. 구조 선택app, package, infra, docs boundary를 고른다.
  4. 모듈 정책TypeScript 사용 여부를 확인하고 ESM module policy를 package, env, codegen 경계에 반영한다.
  5. 운영 경계env, codegen, DB migration, test, health/readiness, observability 위치를 정한다.
  6. instruction docs의미 있는 boundary folder에 짧은 folder-local instruction docs를 둔다.
  7. 완료 형태최종 tree와 validation command를 함께 제시한다.

보안 경계

표시해야 할 경계

  • agent tool, MCP, external API, DB shell
  • migration, deploy script, destructive command
  • secret, scrubbed artifact, generated artifact
  • test, security, health/readiness, observability

금지와 예외 승인

  • Supabase service-role key와 MongoDB URI를 client 또는 shared package에 두는 구조
  • 외부 도구 때문에 CommonJS fallback을 임의로 추가하는 결정
  • 사용자 요청 없이 Pulumi, AWS, Docker 배포 구조를 추가하는 변경
  • source artifact와 generated artifact가 같은 소유권으로 섞이는 tree

파일 관계와 검증

  • 기준 문서skills/project-structure/SKILL.md가 agent가 따르는 원문이다.
  • 사람용 안내skills/project-structure/skill.html은 같은 폴더의 읽기용 요약이다.
  • 참조 문서skills/project-structure/references/는 backend, frontend, DB, desktop, env, folder agents, infra, monorepo, TypeScript module policy 같은 세부 기준을 담는다.

  • 고유 검증node skills/project-structure/scripts/validate-project-structure.ts skills/project-structure
  • HTML 검증node scripts/validate-skill-html.ts .
