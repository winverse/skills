요약

GitHub PR을 만들거나 정리하기 전에 branch, base/head, remote, gh auth, 기존 PR 상태를 확인한다.

  • 사용할 때GitHub PR을 만들거나 정리하기 전에 branch, base/head, remote, gh auth, 기존 PR 상태를 확인한다.
  • 주요 입력현재 branch, diff, issue link, PR 의도, reviewer/label/base/head 요청.
  • 주요 출력한국어 PR title/body, scope summary, validation, risk/rollback, gh pr create/update 결과.
  • 먼저 판단commit 생성은 atomic-committer에 맡기고, merge/close/force-push는 명시 요청 없이는 하지 않는다.
  • 검증관련 validator와 node scripts/validate-skill-html.ts .로 확인한다.

사용 판단

이 화면은 스킬을 설치하거나 적용하기 전에 “언제 쓰고 무엇을 확인해야 하는지”를 빠르게 보여준다.

중요한 기준

  • PR title과 body는 한국어로 작성한다PR title과 body는 한국어로 작성한다. code identifier, 명령, 파일 경로, GitHub 용어는 원문을 유지할 수 있다.
  • 기준.github/pullrequesttemplate.md가 있으면 우선 사용하고, 없더라도 같은 구조를 따른다.
  • 스킬 변경 PR은 skills//스킬 변경 PR은 skills//.md가 한국어 우선 문서라는 규칙을 본문에 적고, node scripts/validate-korean-markdown.ts . 실행 여부를 validation에 남긴다.
  • 검증검증: 실제 실행한 test, validator, browser check, 미실행 항목을 구분한다.
  • 위험위험: migration, secret, permission, UI, runtime, infra 영향이 있으면 적는다.
