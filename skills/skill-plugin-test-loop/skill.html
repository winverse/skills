스킬 이름: skill-plugin-test-loop

스킬과 플러그인을 실제 호출 반복으로 검증한다

새 복제본 또는 격리 복사본에서 실제 첫 응답, 생성 산출물, 검증 결과, 실패 분류를 기록한다. 개선점이 나오면 개선 -> 검증 -> atomic-committer -> GitHub fresh clone 재실행 순서를 지켜 최종 pass와 사전 검증을 구분한다.

대상 고정 상위 스킬, 플러그인, plugin-bundled skill 중 무엇을 검증하는지 entrypoint와 함께 기록한다.
외부 격리 루트 기본 테스트 위치는 repo 밖 external scratch root다. 예시는 <desktop>/skill-plugin-test-runs/<target-slug>다.
출처 고정 remote URL, branch, commit, submodule 상태를 먼저 남긴다. commit/push 전 변경은 fresh clone pass가 아니라 preflight 또는 local-only로만 기록한다.
실제 호출 기록 예상 흐름을 끼워 넣지 않고 prompt, 첫 응답, 실행 기록, 산출물을 그대로 보존한다.
실패 후 새 반복 실행 기록을 고쳐서 통과시키지 않는다. 출처 스킬이나 테스트 방법을 고친 뒤 cycle-NNN을 증가시킨다.
리서치 기반 개선 외부 관행이 중요한 스킬은 web-research로 source lane을 나누고 adopt/adapt/reject/defer 판단을 남긴다.
bounded runner helper가 있으면 session id, 같은 cwd, source commit, timeout, stdin boundary, output path, final response를 확인한다.

사용 판단

  • 새 스킬, 기존 스킬, 플러그인, plugin-bundled skill을 실제 사용자 호출 흐름으로 시험할 때 사용한다.
  • 새 복제본, 격리 복사본, 반복 기록, 실제 질문/응답, 산출물 폴더, 실패 원인 분류가 필요할 때 사용한다.
  • 일반 앱 테스트만 돌리면 되는 경우에는 대상 repo의 테스트 실행기를 쓴다.
  • 결정적 라우팅, schema, safety 평가 사례만 추가하는 작업은 agent-eval-harness가 주 스킬이다.

작업 흐름

1

대상과 출처

entrypoint, local 또는 remote 출처, branch, commit, submodule 상태를 고정한다.

2

publish gate

검증할 변경이 commit/push되어 있지 않으면 preflight 또는 local-only로만 보고 fresh clone pass로 기록하지 않는다.

3

외부 격리 루트

Desktop 같은 repo 밖 경로에 test root를 만들고 current/만 매 cycle 삭제한다.

4

새 clone

current/_github/<repo>에 GitHub 새 복제본을 받고 downloaded commit을 기록한다.

5

리서치 판단

best practice나 유명한 workflow 비교가 필요하면 web-research lane을 켠다.

6

사례 실행

정상 경로와 의심 경계 사례를 실제 prompt로 호출하고 첫 응답을 저장한다.

7

증거 저장

실행 기록, 산출물, 검증기 출력, 브라우저 증거를 runs/cycle-NNN 아래에 둔다.

8

분류와 반복

실패 분류를 기록하고 출처 스킬 또는 테스트 방법을 고친 뒤 검증, commit/push, 새 clone 재실행으로 다음 반복을 실행한다.

격리 실행 기준

단계 통과 기준 실패로 보는 경우
commit/push GitHub clone이 받을 변경은 먼저 atomic-committer로 commit/push되어 있다. commit/push 전 작업본을 clone처럼 취급하거나 최종 pass라고 부른다.
외부 test root Desktop 같은 repo 밖 경로에서 실행하고 runs/를 보존한다. target repo 내부 scratch나 symlink에 의존한다.
새 복제본 current/_github/<repo>를 매 cycle 새로 만든다. 이전 cycle의 current/를 재사용한다.
필수 publish loop 개선 -> 검증 -> atomic-committer로 commit/push -> Desktop 외부 루트에서 GitHub fresh clone 재실행 순서를 남긴다. 검증만 하고 remote source를 갱신하지 않은 상태를 fresh clone 검증으로 보고한다.

보안 경계

금지

기대 결과를 실행 기록에 끼워 맞추거나 같은 반복 기록을 덮어쓰지 않는다. 새 복제본 검증을 요구받았는데 local workspace, symlink, global install에 몰래 기대지 않고, commit/push 전 cycle을 최종 pass라고 부르지 않는다.

허용

현재 runtime이 원본 skill, plugin, command를 실제 호출할 수 없으면 fallback으로 표시하고 누락된 호출 가능 표면을 기록한다.

bounded runner 기준

확인 항목 요구 기준 실패 분류
실행 식별자 명시적인 session id 또는 run id가 있고 같은 cwd와 같은 source commit으로 실행한다. runner
입출력 경계 stdin boundary, prompt file, output file 경로를 기록하고 이전 세션 tail에 의존하지 않는다. runner 또는 test method
시간 제한 timeout을 둔다. timeout이나 final response 누락은 성공으로 보지 않는다. runner

실패 분류

분류 의미
skill contract 스킬 문구가 실제 호출 조건, 순서, 산출물, 금지 경계를 충분히 강제하지 못했다.
plugin contract manifest, bundled skill, MCP, hook, 출처 경계가 실제 plugin 사용과 다르다.
runner helper script, timeout, session, stdout/stderr capture, final response 수집 문제다.
test method 테스트가 실제 호출이 아니라 결과를 끼워 맞췄거나 local workspace를 몰래 사용했다.
target artifact 생성된 프로젝트, 문서, 실행 기록, 검증기 출력이 요구 형태와 다르다.
environment/hook shell, terminal, hook approval, MCP startup, 권한, installed binary 문제다.
source drift README, snippet, catalog, 실행 기록, 검증기, plugin registry가 서로 어긋났다.
