feature-workflow

이미 존재하는 PRD, issue, bug repro, acceptance criteria, ADR, design.md를 검증 가능한 구현 루프로 바꾸는 반복 실행 스킬입니다.

원본SKILL.md
시각 guideskill.html
전용 검증scripts/validate-feature-workflow.ts
상위 registrydocs/update-source-registry.md

raw idea, 제품 탐색, 구조 선택이 남아 있으면 이 루프가 아니라 project-workflow로 되돌립니다.

기능 구현spec → plan → TDD 버그 수정repro → 최소 수정 UI 변경design review → QA 큰 구현claim → fan-out

모드를 바꾸면 같은 루프에서 강조되는 시작 근거만 달라집니다. 공통 gate는 work-claims.md, TDD evidence, review, QA, document sync입니다.

1. 기존 근거가 있을 때만 시작spec, issue, PRD, ADR, design.md, bug repro가 authority입니다.
2. primitive는 출처와 상태를 표시Superpowers, GStack, Matt Pocock, repo-local helper를 selected/skipped/fallback으로 남깁니다.
3. claim 충돌은 overlap block다른 active lane이나 shared/hotspot file과 겹치면 멈춥니다.
4. 완료는 증거 묶음으로 판단RED/GREEN/REFACTOR, QA, docs sync, TypeScript module 정책까지 보고합니다.

사용 판단

요청이 어떤 lane에 들어가는지 먼저 가르고, 초기 기획이 부족하면 즉시 넘깁니다.

사용새 feature issue 구현spec preflight → implementation plan → TDD evidence로 이동합니다.
사용버그 수정reproduce 또는 characterization check를 RED로 남기고 최소 수정합니다.
사용substantial UI specdesign.md나 selected mock을 확인하고 design review와 browser QA를 붙입니다.
사용large implementationwriting-plans, plan-eng-review, disjoint write set을 거친 뒤 fan-out합니다.
대체CLI/no-browser spec브라우저 대신 command, API fixture, log 같은 runtime evidence를 남깁니다.
완료completionreview, QA, document sync, commit handoff 필요 여부를 확인합니다.
차단raw project idea도메인, 제품, 구조가 비어 있으면 project-workflow handoff입니다.

작업 흐름과 금지 경계

화살표는 실제 node에 닿고, 각 단계는 다음 증거나 중단 결정으로 이어집니다.

보안 경계 gate

허용근거 파일을 읽고, 현재 lane의 claimed write set 안에서 production edit을 수행합니다.
금지다른 active lane과 겹치는 파일, shared/hotspot file, read-only path를 임의로 수정하지 않습니다.
허용RED evidence가 어려우면 이유와 대체 evidence를 workflow log에 남깁니다.
금지RED/GREEN 편의를 위해 require, module.exports, .cjs, .cts를 추가하지 않습니다.

증거 공개 패널

클릭하면 completion report에 들어가야 할 증거 모양이 바뀝니다.

claim gatework-claims.md와 overlap block TDD 증거RED / GREEN / REFACTOR QA 증거browser 또는 command runtime 문서 동기화docs drift와 handoff

production edit 전 claim 확인

work-claims.md가 있으면 현재 lane의 claimed write set, read-only paths, shared/hotspot files, integration owner를 확인합니다.

겹침이 있으면 overlap block으로 멈추고 조정 요청을 남깁니다.
