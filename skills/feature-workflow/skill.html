FEA

feature-workflow

기존 PRD, issue, spec, bug report, acceptance criteria, design.md, ADR을 기준으로 하나의 feature, bug fix, vertical slice를 TDD, 구현 계획, review, QA, 문서 동기화까지 끝내는 반복 실행 루프다.

에이전트 원본SKILL.md
사람용 가이드skill.html

사용 판단 매트릭스

이미 방향이 잡힌 구현 요청인지 먼저 가른다.

사용

PRD, issue, spec, bug 재현, acceptance criteria, ADR, design.md가 있고 코드 변경과 검증이 필요한 경우 사용한다.

연결

code-review, browser-qa, design-review, sync-docs, agent-eval-harness를 필요한 단계에만 붙인다.

되돌림

raw idea, 제품 발견, 구조 선택, design system 초기화가 부족하면 project-workflow로 넘긴다.

중단

work-claims.md의 active lane과 쓰기 범위가 겹치거나 shared/hotspot 파일 owner가 아니면 overlap block으로 멈춘다.

실행 경계 관계도

feature-workflow는 초기 셋팅 이후 반복 구현을 맡는 별도 skill입니다. project-workflow plugin과 합치지 않습니다.

기본 실행 루프

화살표는 실행 순서를 나타내며 각 endpoint는 보이는 node에 닿는다.

1. preflightlocal instruction, spec authority, state cache, work claim, TypeScript module 정책, tool risk gate를 먼저 확인한다.
2. plan필요한 primitive만 selected, skipped, fallback으로 표시하고 작은 검증 단위로 나눈다.
3. TDD 또는 characterizationproduction change 전 RED evidence를 남기고, 구현 후 GREEN과 필요한 REFACTOR 검증을 남긴다.
4. review, QA, docs sync코드 리뷰, 브라우저 또는 CLI runtime evidence, 문서 drift 정리, completion handoff를 마친다.

파일 관계도

이 폴더의 원본, guide, 참조, validator를 분리해서 본다.

SKILL.md스킬 실행 계약과 호출 조건. references/upstream-dependency-map.md외부 primitive 출처와 갱신 규칙. references/feature-workflow-playbook.md긴 운영 기준과 예시. scripts/validate-feature-workflow.tsfeature-workflow 전용 검증기.
TypeScript module 정책

production edit이면 type: "module", ESM tsconfig, import/export를 유지하고 CommonJS 금지 원칙에 따라 require, module.exports, .cjs, .cts를 새로 추가하지 않는다.

Agent Tool And Security Risk Gate

tool, MCP, external API, file write, network, untrusted content가 있으면 구현 전에 gate 결정과 제약을 기록한다.

completion handoff

acceptance criteria, tests 또는 runtime evidence, review 처리, docs sync, artifact hygiene를 완료 전에 확인한다.

eval seed

잘못된 route, 누락된 QA, skipped TDD, tool gate 실수가 반복될 위험이면 agent-eval-harness 후보를 남긴다.
