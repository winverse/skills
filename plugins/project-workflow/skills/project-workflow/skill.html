project-workflow

새 프로젝트와 큰 기획을 바로 구현하지 않고, 도메인 언어, 제품 검증, 구조 결정, 디자인 기준, PRD, 이슈 목록, 구현 인계 조건으로 정리하는 초기 셋팅 스킬입니다. 이 plugin-bundled 파일은 project-workflow의 canonical source입니다. Top-level `skills/project-workflow` 경로는 제거됐고 plugin 경로만 정본입니다.

핵심 계약

실행을 바꾸는 5개 계약만 첫 화면에서 확인합니다.

정본 경로plugin-bundled skill만 정본 계약을 유지하고, 새 project instruction은 plugin 경로를 직접 링크합니다.
질문 gate 우선raw idea에서는 grill-with-docs, office-hours, brainstorming setup gap check 전에는 PRD와 구조 인계를 확정하지 않습니다.
실제 호출 우선선택한 primitive는 호출면을 확인해 실제 호출하고, 불가능하면 fallback 상태와 local 질문을 남깁니다.
책임 분리구조는 project-structure, 반복 구현과 TDD와 QA는 feature-workflow, 문서 drift는 sync-docs로 넘깁니다.
위험 gatetool, MCP, external API, file write, network, untrusted content는 Agent Tool And Security Risk Gate를 먼저 기록합니다.

사용 판단 매트릭스

요청이 초기 셋팅인지, 구조 인계인지, 구현 인계인지 먼저 나눕니다.

사용

새 서비스, 새 앱, 큰 기획, raw idea를 도메인 문서, 제품 검증, ADR, PRD, 이슈 목록으로 정리할 때 사용합니다.

연결

폴더와 인프라 경계는 project-structure, 문서 동기화는 sync-docs, 반복 구현은 feature-workflow에 넘깁니다.

대기

raw idea나 새 프로젝트에서 grill-with-docs, office-hours, Superpowers brainstorming setup gap check가 끝나지 않았으면 PRD와 이슈 목록을 확정하지 않습니다.

차단

비밀값, 외부 쓰기, MCP, API, 네트워크, 파일 쓰기 자동화가 있으면 Agent Tool And Security Risk Gate를 먼저 기록합니다.

초기 셋팅 흐름

질문, 결정, 산출물, 인계가 순서대로 쌓여야 합니다.

1. 호출면 확인

현재 session의 skill list, enabled plugin list, slash command, MCP/tool, project instruction 링크 순서로 실제 호출 가능 여부를 기록합니다.

2. 질문 gate

도메인 질문, 제품 challenge, Superpowers brainstorming setup gap check를 순서대로 처리합니다.

3. 결정 gate

ADR, TypeScript ESM only, 디자인 방향, tool/security decision을 PRD와 이슈보다 먼저 둡니다.

4. 인계 gate

workflow-state.md와 필요한 경우 work-claims.md를 남긴 뒤 구현 단위만 feature-workflow로 보냅니다.

질문 gate와 범위 축소

답이 없으면 추정으로 확정하지 않고 열린 질문으로 남깁니다.

도메인핵심 객체, 피하고 싶은 오해, 기존 용어와 새 용어의 경계를 확인합니다.
제품해결할 고통, 첫 사용자, 지금 당장 쓸 수 있는 가장 좁은 성공 장면을 묻습니다.
범위이번 셋팅에 포함할 것, 제외할 것, 나중으로 미룰 것을 나눕니다.
확신도확정된 답, 추정한 답, 반드시 다시 물어야 할 답을 분리합니다.
대기 조건사용자가 “추정해서 진행”이라고 명시하지 않으면 질문이 끝나기 전 PRD, issue backlog, architecture handoff를 확정하지 않습니다.

병렬 작업 조정

work-claims.md는 권위 문서가 아니라 겹침을 막는 조정 산출물입니다.

lane 소유권lane id, owner/session, branch 또는 worktree, spec/issue target을 기록합니다.
쓰기 경계claimed write set, read-only paths, shared/hotspot files, integration owner를 분리합니다.
완료 증거status, validation command, evidence path를 남기고 구현은 feature-workflow에서 진행합니다.

큰 구현 인계

여러 단계로 나뉘는 구현은 실행기가 아니라 agent-neutral 인계 계획으로 먼저 고정합니다.

phases/index.jsonproject, phase, steps, status를 담고 상태값은 pending, completed, error, blocked로 제한합니다.
step<N>.mdread files, 작업 범위, claimed write set, acceptance commands, blocked conditions, 금지사항을 각 단계에 적습니다.
실행 경계plugins/project-workflow/scripts/execute-phase.ts는 dry-run이 기본이며, 실제 실행은 사용자가 --agent-bin과 필요한 --agent-arg를 명시했을 때만 허용합니다.

완료 조건

Claude Code에서는 /goal, 다른 runtime에서는 같은 내용을 completion checklist로 남깁니다.

판단 가능한 끝CONTEXT.md, ADR, PRD, issue backlog, design.md, setup validation처럼 확인 가능한 산출물을 지정합니다.
검증 증거agent가 transcript에 남길 명령, 파일 경로, evidence path를 미리 정합니다.
제약건드리면 안 되는 파일, secret, destructive action, scope 바깥 작업을 명시합니다.
한계8 turns 후 중단처럼 시간, turn, 항목 수의 상한을 둡니다.
평가 방식/goal evaluator가 파일을 직접 읽지 않는다고 보고, 필요한 증거를 출력에 남기게 합니다.

파일 관계

이 스킬 폴더에서 사람이 확인할 주요 파일입니다.

SKILL.md에이전트가 따르는 호출 조건과 실행 계약입니다. canonical SKILL.mdplugin으로 이동한 정본 실행 계약입니다. skill.html사람이 빠르게 읽는 도표 중심 가이드입니다. docs/update-source-registry.mdsource id, URL, checked date, local 판단의 단일 source registry입니다. references/upstream-dependency-map.mdprimitive 사용 순서, 채택 역할, handoff 규칙입니다. references/project-workflow-playbook.md긴 운영 기준과 세부 예시를 둡니다. scripts/validate-project-workflow.ts스킬 전용 검증기를 둡니다. execute-phase.ts큰 구현 인계 계획의 선택적 TypeScript dry-run 도구입니다.
